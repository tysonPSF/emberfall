## Architecture rules

- **All state changes go through the `World` autoload** (`scripts/autoload/world.gd`). Input and UI call `World.request_*(entity_id, ...)` with ids, never mutate Entity stats/inventory directly. These functions become server RPCs later; keep them id-based and self-validating (range, ownership, dead checks).
- Networking is the `Net` autoload (`scripts/autoload/net.gd`): a dedicated server (`--server`) runs World; clients mirror entities (puppets under the server's ids) and forward every `request_*`. Every new `request_*` must start with `if _remote(&"request_x", [args...]): return`, and HUD signals for one player go through `World._ui(p, &"signal", [args])`, never `signal.emit()`. Rules run only where `Net.is_authority()`; mobs/npcs/corpses on a client must not simulate. A server-side change to a player's position must call `Net.teleport(p, pos)`. A client walking into a zone line stands still there (`Player._zone_hold`, up to 8 s) until the server moves it: a live server can take seconds to build a zone the first time, and the map's edge is only a few steps past the line. Falling out of the world puts you back on your `last_ground` in that zone. Zone-line triggers are 40 m tall, so a jump, a fall or a floating player still counts. Connections wait up to a minute before giving up (`Net._be_patient`: ENet's default drops after as little as 5 s, and a slow server building a zone stalls longer). The server log gives each zone's build time; `--preload-zones` builds them all at startup (about 1.8 GB). Test a slow server with `EMBERFALL_ZONE_DELAY=<ms>` on the server and `--nettest=Zoner --north` (runs Greenmoor's north pass with real movement). A server runs every zone someone is in (or was recently) at once, each in its own SubViewport world with overlapping coordinates; a zone left empty past its slowest respawn (at least 15 minutes) with no player corpse or dropped item in it is taken down and built again on the next visit, so a returning player can't tell (`main._watch_idle_zones`, `Zone.keep_reason`, `idle_seconds_to_unload`; the start zone and `--preload-zones` stay up; test with `EMBERFALL_ZONE_IDLE=<seconds>` on the server and `--nettest=Zoner --round-trip` twice): find an entity's zone with `World.zone_of(node)` (never `World.zone`, which is only the client's/offline current zone), and compare positions only through `Entity.distance_to`, which is infinite across zones. Groups live in `World.groups` (server); a player's `group` array is the view their HUD draws, pushed with their state. Mob kills credit the top damage dealer's group (`_kill_credit`, `_award_group`; members within `group_xp_level_gap` (config, 10) levels of the highest share the experience, `World.xp_eligible`); spells with `"target": "group"` land on every member in range. Online characters live on the server (`AccountStore`, `scripts/server/account_store.gd`, under `--data`); clients never send saves, only the one-time import of an offline character.
- Player-facing messages go through `World.say(entity, text, color)`, not `log_message.emit`, so they can be routed per-connection later.
- Content is data: add mobs/items/spells/zones in `data/*.json`, not code. JSON numbers parse as float, so cast with `int()`.
- Nodes are built in code (no hand-authored scenes besides `scenes/main.tscn`). `Entity.make_visual(look)` builds either a rigged model or placeholder primitives.
- Art is KayKit (CC0) in `assets/`, referenced by id through `data/models.json`. All characters share the `Rig_Medium` skeleton, so one animation library (`CharacterModel.library()`) drives every model and weapons attach to bone `handslot.r` (shields to `handslot.l`). `models.json` `"grips"` turns and offsets a held model and can move it to another bone; with `"orient"` it rides one bone (`pos` on it, `out` in the orient bone's frame) but keeps another's orientation, which is how shields work: at the forearm, oriented by the chest, so they hang upright at your side whatever twist the walk puts in the arm. Try values with `--lineup=knight --action=walk --offhand=shield_round --grip=x,y,z,px,py,pz,bone,orient,ox,oy,oz` (the `behind_left` view is the gameplay angle). Poses the free packs lack (sitting on the ground) are built by `tools/blender/anims.py` on the same rig into `assets/animations/Rig_Medium_Extra.glb`, listed last in `models.json` `"animations"`; its `.import` keeps immutable tracks, or bones a clip holds still would keep the previous clip's pose. Use the glTF files; the fbx/obj folders carry `.gdignore`. Classes, mobs and items pick art with `model` / `weapon` fields.
- Creatures KayKit lacks (rat, fire beetle) are generated by `tools/blender/creatures.py`, which models, rigs and animates them from primitives and exports to `assets/creatures/`. They use `"rig": "own"` in `models.json` and carry their own clips named after actions (`idle`, `walk`, `run`, `attack`, `hit`, `death`); `CharacterModel` maps actions to KayKit clip names for everything else. It also builds bolt-on parts (gnoll head, tail): a `models.json` entry can reskin a KayKit body with `hide` (mesh parts), `tint` (multiplies a part's texture) and `attach` (scenes pinned to bones, authored in KayKit mesh space). Rebuild with `/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup -P tools/blender/creatures.py -- --out assets/creatures [--preview <dir>]`.
- Worn gear looks EverQuest-style first: `models.json` `"body_parts"` maps a wearable to another KayKit model's parts (`Knight_LegLeft`, `Rogue_Body`, `Skeleton_Rogue_Hood`...) with an optional `tint`; `CharacterModel.set_worn` copies them onto the wearer's skeleton (skins bound by bone name, rigid hats on their bone) and hides the wearer's own parts listed in `covers`. KayKit arms end in hands and legs in feet, so gloves and boots only swap arms/legs when no sleeves/pants do. A model's `"part_swaps"` limits which slots swap (skeletons: no arms, or they'd grow flesh hands); anything else falls back to the rigid gear.py pieces below.
- Worn gear is modeled in `tools/blender/gear.py` (KayKit character mesh space, Dungeon palette via props.py's Prop helpers) as rigid pieces pinned to bones: headgear on `head`, tunics on `chest`, belts on `spine`, gloves/sleeves/boots/leg plates on the `.l` bones (built left, exported mirrored as `_r`). `models.json` `"gear"` lists each wearable's pieces (regenerate with `--manifest <file>`); an item's `"wear"` field picks the wearable. Players hide their class model's own hat (`"headgear_parts"`) and show exactly what they wear; mobs show what they spawned with in their model's `"wearable_slots"`. `look.worn` carries it to other players. Rebuild with `/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup -P tools/blender/gear.py -- --out assets/gear [--preview <dir>]` (the preview dresses every class in cloth, leather and iron outfits).
- World props live in `models.json` `"props"` and are placed by `Zone._prop(id, pos, yaw, scale, collide)`. KayKit Dungeon pieces (walls, floors, barrels, banners) use `"scale": 0.75` to match our 0.75-scale characters. Props the pack lacks (trees, boulders, tent, campfire, obelisk, palisade, torch post, banner pole) come from `tools/blender/props.py`, in game meters, UV-mapped onto the pack's palette texture (`dungeon_texture.png`, an 8x4 grid of vertical gradients) so they match its colors and shading. New props should use the same `Prop` helpers and swatches. Buildings should match the KayKit houses: build their stone out of the pack's own pieces with `kaykit(piece, loc, rot_z, scale)` and `join_into` (the tavern's walls, windows, pillars), and give everything hand-modeled `Prop.build(bevel=0.06)` so edges are rounded like KayKit's.
- **Before creating or connecting a zone, read `docs/zone-implementation.md`.** The world's shape is settled: 37 zones in 6 areas, levels 1-50, laid out in `docs/world-layout.json` (`docs/world-map.png` is the picture) and verified by `tools/world_layout.py`. A border is FOUR things that must agree - a `passes` entry and a `zone_lines` entry on each side - so derive all four from the layout's `links` rather than authoring them per zone; that brief gives the arithmetic, measured off Emberhold, Greenmoor and Thornwood. Do not add a zone, move a cell or invent a border outside `tools/world_layout.py`, and do not give The Grove a pass, a zone line or a cell: it is teleport-only and its isolation is asserted.
- Zones are `data/zones/<id>.json`. Besides terrain, trees and spawns they hold `landmarks` (typed builders in `zone.gd`: obelisk, camp, ruins, outpost, wall_ring, hearth_plaza, house, market, signpost, cave, prop), `roads` (dirt polylines, optional `road_lamps` spacing), `passes` (gaps in the mountain ring), `zone_lines` (trigger box -> `to` zone + `arrive` point), `npcs`, and `clutter` (grass/flowers/bushes per m², drawn as chunked MultiMesh with `scripts/world/clutter.gdshader`; grass is modeled white and tinted to the ground). `main.gd` owns zone switching (`World.zone_change`); player corpses are saved per zone. New characters start in `config.starting_zone` (Emberhold); the autotest starts in Greenmoor.
- **Before creating or connecting any zone, read `docs/zone-implementation.md`.** The world is a grid of 37 zones in `docs/world-layout.json` (human version `docs/world-layout.md`, picture `docs/world-map.png`), the source of truth for where each zone is, its size and levels, and who it borders. Every border (a pass and a zone line on both sides, and the arrive points) is derived from the layout's `links`, never typed by hand. `python3 tools/world_layout.py` re-checks the layout and rewrites `docs/world-layout.json` (`python3 tools/render_map.py` redraws `docs/world-map.png` from it; needs matplotlib); `python3 tools/atlas_map.py` redraws the parchment atlas `docs/world-atlas.png` (needs scipy and scikit-image; its fonts (TeX Gyre Chorus and Pagella, Latin Modern caps, GFS Baskerville) are looked up by file name in `EMBERFALL_FONTS` when set); do not add zones, move cells or invent borders outside it. Interiors (the tavern) and dungeon instances are off the grid: they are reached through a door or zone line inside a zone, not a pass.

- Items live in `data/items/*.json` (weapons, armor, jewelry, drops, rewards); every file in the folder is merged, so add a new file for a new quest line instead of editing a shared one. Slots: primary, secondary (shields, shown in the left hand), head, neck, arms, hands, chest, waist, legs, feet, ring (fits ring1/ring2).
- Skills are EQ-style (`data/skills.json`): per-class caps of per_level x (level + 1), raised by use via `World.try_skill_up` (never from gray targets). Weapons name their `"skill"`; spells name their school or ability skill. Effects are measured against 80% of cap (`tuning.neutral`), where combat is exactly the base rules: weapon + offense adjust hit and damage, defense lowers the enemy's hit, block/parry/dodge avoid swings, school skill sets fizzles, channeling resists interruption from hits, meditate scales resting mana, and kick/bash/bind wound/taunt scale with their skill.
- Inventory is EQ-style: `Pack` (`scripts/core/pack.gd`) holds 8 general slots of entries `{item, count[, contents]}`; bags (`"bag": n` items in `data/items/containers.json`) hold entries but never other bags. Places are strings: `g:3`, `b:3:5` (bag in general 3, slot 5), `e:head`, `k:7` (bank), `t:2` (trade). Items move through the server-side cursor: `World.request_click(player, place)` picks up or puts down/swaps, `request_pick_one` splits a stack; shift-click shortcuts (`request_equip`, `request_sell`, `request_bank_deposit`, `request_trade_add`) take a place too. Never touch a flat item list: use `p.pack` (`add`, `remove`, `count`, `room_for`, `item_ids`) and `p.owned_item_ids()`. Giving: a click on an npc with an item on the cursor calls `World.request_give` (opens a trade, even with a merchant, and puts the item in it); G on a merchant opens a trade instead of the shop when `_hand_in_waiting` (you carry everything for one of their quests). Dropping: with an item on the cursor, a click on the world calls `World.request_drop` (NO DROP, or a bag holding one, is refused), which leaves a `GroundItem` (`scripts/entities/ground_item.gd`, the whole entry, bags with contents) in the zone for 15 minutes; clicking it calls `request_pickup` (cursor first, else the pack; lore checked). The flight is only a picture: `World.shot_fired` -> `Projectile.launch` on every machine that draws (`Net.broadcast_shot` online).
- Loot is EQ-style: humanoid mobs roll `gear` (mobs.json, tables in `data/loot.json`) when they spawn, show it (weapon in hand; `gear_parts` in models.json name the mesh parts shown per slot) and drop it on death. Dropped gear carries a quality in its id (`iron_dagger@fine`); always read items through `GameData.item(id)` / `item_name`, never `GameData.items[id]` directly. Quality odds rise with mob level and `"named": true`. Each tier's `"finish"` in `loot.json` (tint, metallic, roughness, rim, glow) shows on the gear itself: `look.tiers` ({slot: tier}, from `GameData.gear_tiers`) goes with the look, and `CharacterModel.set_tiers` refinishes held and worn meshes (originals are kept on each mesh, so finishes never stack). Compare with `--lineup=barbarian,barbarian,barbarian --tiers=crude,,masterwork --weapon=sword_1handed --worn=head:iron_coif`.
- Music is original, composed by `tools/audio/music.py` (numpy synthesis: harp, lute, flute, pad, bass, frame drum, bell, convolution reverb; seeded phrase-by-phrase melody over a chord progression per section) and encoded to `assets/music/<track>.ogg` by Blender's FFmpeg: `/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup -P tools/audio/music.py -- --out assets/music [--only greenmoor]`. A zone names its theme with `"music"`; the `Music` autoload loops it and crossfades on zoning (title screen: `title`). `combat` fades in over the zone theme (buses "MusicZone" / "MusicCombat" under "Music") while `Player.threatened` (server: any living mob hates you, sent with the player's state) and gives way after 4 calm seconds. Volume is `Controls.music_volume` (default 25%) on the "Music" bus, in Settings and the Esc menu; test runs are muted. `settings.json` is shared by `main.gd` and `Controls`, so always rewrite one key (`Controls._save_setting`), never the whole file.
- Pathfinding: where the rules run (server/offline), each zone bakes a navigation mesh at load on a background thread (`Zone._bake_navigation`, from the terrain and every WORLD-layer collider; `nav_ready`). Mobs and guards move with `Entity.nav_dir(goal, delta)`: straight at the goal when a ground-following knee-height ray (`_clear_line`) says nothing's in the way, else along `NavigationServer3D.map_get_path`, re-planned only when the goal moves (at most every 0.6 s, staggered); `nav_snap` keeps wander targets walkable. Anything solid you add blocks mobs as long as it collides on `Layers.WORLD`. Tests: `nav_bake`, `nav_chase` (`Entity.nav_enabled` turns it off to compare).
- Performance: mobs and NPCs standing still on the ground skip `move_and_slide` (most of a zone's physics cost otherwise); night lights fade out with distance (`distance_fade_*`, shadows only within ~22 m). Check a heavy zone with `--autotest --only=hollowmere_perf,night_isolate,physics_isolate`. A dedicated server caps itself at 60 FPS (`main.SERVER_FPS`; headless has no vsync) and skips looks (`Net.dedicated`, set before the first zone is built: no animation, nameplate colors, guard torches or `DayNight`). Its idle cost is mostly each loaded zone's physics, a few ms a frame each even with nobody there (all 14 zones preloaded ran a desktop server at about 5 FPS), which is why empty zones are taken down.
- Server updates: `tools/server/auto_update.sh` (run by `emberfall-update.timer`, or on demand by `tools/server/deploy.sh` over SSH) pulls `main` when it changed; it writes `restart_notice` (players are warned) and then `restart_now` into the server's `--data` folder, which `main.gd` `_watch_for_updates` polls: it saves everyone and quits with code 3, and systemd (`Restart=always`) starts it again. Setup: `docs/server-updates.md`.
- Balance: `scripts/dev/balance_sim.gd` (autotest section `balance`, run headless: `godot --headless --path . -- --autotest --only=balance`, optionally `BALANCE_ONLY=warrior,rogue` and `BALANCE_DEBUG=1`) fights every class (and each magician pet) against three typical monsters at levels 5-25 under the real rules at 20x speed, in a cleared corner of Greenmoor, and writes `user://balance.json` (kill time, health and mana spent, rest, deaths, levels per hour). Rerun it after changing class, spell, pet, gear or monster numbers.
- Physics layers are in `scripts/core/layers.gd`. Entities don't collide with each other.
