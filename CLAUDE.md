# Emberfall

Classic-EverQuest-style RPG in Godot 4.7 (GDScript). Solo slice now; multiplayer/grouping planned.

## Architecture rules

- **All state changes go through the `World` autoload** (`scripts/autoload/world.gd`). Input and UI call `World.request_*(entity_id, ...)` with ids, never mutate Entity stats/inventory directly. These functions become server RPCs later; keep them id-based and self-validating (range, ownership, dead checks).
- Player-facing messages go through `World.say(entity, text, color)`, not `log_message.emit`, so they can be routed per-connection later.
- Content is data: add mobs/items/spells/zones in `data/*.json`, not code. JSON numbers parse as float, so cast with `int()`.
- Nodes are built in code (no hand-authored scenes besides `scenes/main.tscn`). `Entity.make_visual(look)` builds either a rigged model or placeholder primitives.
- Art is KayKit (CC0) in `assets/`, referenced by id through `data/models.json`. All characters share the `Rig_Medium` skeleton, so one animation library (`CharacterModel.library()`) drives every model and weapons attach to bone `handslot.r`. Use the glTF files; the fbx/obj folders carry `.gdignore`. Classes, mobs and items pick art with `model` / `weapon` fields.
- Creatures KayKit lacks (rat, fire beetle) are generated by `tools/blender/creatures.py`, which models, rigs and animates them from primitives and exports to `assets/creatures/`. They use `"rig": "own"` in `models.json` and carry their own clips named after actions (`idle`, `walk`, `run`, `attack`, `hit`, `death`); `CharacterModel` maps actions to KayKit clip names for everything else. It also builds bolt-on parts (gnoll head, tail): a `models.json` entry can reskin a KayKit body with `hide` (mesh parts), `tint` (multiplies a part's texture) and `attach` (scenes pinned to bones, authored in KayKit mesh space). Rebuild with `/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup -P tools/blender/creatures.py -- --out assets/creatures [--preview <dir>]`.
- World props live in `models.json` `"props"` and are placed by `Zone._prop(id, pos, yaw, scale, collide)`. KayKit Dungeon pieces (walls, floors, barrels, banners) use `"scale": 0.75` to match our 0.75-scale characters. Props the pack lacks (trees, boulders, tent, campfire, obelisk, palisade, torch post, banner pole) come from `tools/blender/props.py`, in game meters, UV-mapped onto the pack's palette texture (`dungeon_texture.png`, an 8x4 grid of vertical gradients) so they match its colors and shading. New props should use the same `Prop` helpers and swatches.
- Zones are `data/zones/<id>.json`. Besides terrain, trees and spawns they hold `landmarks` (typed builders in `zone.gd`: obelisk, camp, ruins, outpost, wall_ring, hearth_plaza, house, market, signpost, prop), `roads` (dirt polylines, optional `road_lamps` spacing), `passes` (gaps in the mountain ring), `zone_lines` (trigger box -> `to` zone + `arrive` point), `npcs`, and `clutter` (grass/flowers/bushes per m², drawn as chunked MultiMesh with `scripts/world/clutter.gdshader`; grass is modeled white and tinted to the ground). `main.gd` owns zone switching (`World.zone_change`); player corpses are saved per zone. New characters start in `config.starting_zone` (Emberhold); the autotest starts in Greenmoor.
- Faction lives in `data/factions.json` (defaults, `on_kill` / `on_attack` hits, mob `kos_at`); NPCs name theirs in `data/npcs.json`. Standing rules are in `World` (`standing`, `apply_faction`, `refuses`, `mob_kos`, `npc_kos`). Players may fight an NPC only after confirming (double Q) - `World.can_attack` is the single gate for who may hit whom.
- Loot is EQ-style: humanoid mobs roll `gear` (mobs.json, tables in `data/loot.json`) when they spawn, show it (weapon in hand; `gear_parts` in models.json name the mesh parts shown per slot) and drop it on death. Dropped gear carries a quality in its id (`iron_dagger@fine`); always read items through `GameData.item(id)` / `item_name`, never `GameData.items[id]` directly. Quality odds rise with mob level and `"named": true`.
- Physics layers are in `scripts/core/layers.gd`. Entities don't collide with each other.

## Verify changes

```sh
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --import   # parse/compile check
/Applications/Godot.app/Contents/MacOS/Godot --path . -- --autotest --shots=<dir>  # scripted playthrough + screenshots
/Applications/Godot.app/Contents/MacOS/Godot --path . -- --lineup=gnoll,rat --shots=<dir>  # art check: models side by side, 4 angles
```
